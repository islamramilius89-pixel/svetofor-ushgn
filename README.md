# 🚨 Светофор УШГН

Сайт о системе мониторинга и диагностики скважин ПАО «Татнефть». Система анализирует ток
электродвигателя установок скважинных штанговых глубинных насосов (УШГН) и по отклонениям
от эталона находит неисправности оборудования.

Разделы: **Главная**, **О проекте**, **Результаты**, **Контакты** (форма обратной связи
со списком сообщений).

## Стек

- **Next.js 16** (App Router) + **React 19** + **TypeScript**
- **TanStack Query** — данные сервера: загрузка, мутации, кеш
- **Zod** — схемы проверки формы и ответов API
- **Tailwind CSS 4** — стили
- **ESLint** (`eslint-config-next`)

## Запуск

```bash
npm install
npm run dev
```

Откройте http://localhost:3000.

| Команда | Что делает |
|---|---|
| `npm run dev` | режим разработки с горячей перезагрузкой |
| `npm run build` | production-сборка с проверкой типов |
| `npm run start` | запуск собранной версии |
| `npm run lint` | проверка кода ESLint |

## Архитектура

Проект следует скиллу [`next-frontend-architecture`](.claude/skills/next-frontend-architecture/SKILL.md).
Путь вызова: `app → component → flow → interaction → use-case → infrastructure → API`.
Слой создаётся только тогда, когда у него есть своя ответственность.

```
src/
├── app/                         маршруты (серверные компоненты)
│   ├── layout.tsx               общий каркас: шапка, подвал, QueryProvider
│   ├── page.tsx                 /           — главная
│   ├── about/page.tsx           /about
│   ├── results/page.tsx         /results
│   ├── contact/page.tsx         /contact
│   ├── not-found.tsx            страница 404
│   └── api/messages/            Route Handlers: GET, POST, DELETE и DELETE /[id]
├── components/<feature>/        экраны и визуальные части (home, about, results, contact, layout)
├── flows/use-contact-flow.ts    сценарий экрана контактов: форма + список + действия
├── interactions/messages.ts     TanStack Query: ключи, запрос списка, мутации, обновление кеша
├── layers/
│   ├── domain/                  типы, правила и схемы Zod (без React и HTTP)
│   ├── use-cases/               действия приложения (расчёт показателей, отправка и приём сообщения)
│   └── infrastructure/          HTTP-клиент, клиент API сообщений, источник данных, серверное хранилище
├── common/                      общие UI-элементы, провайдер, форматирование
└── assets/styles/globals.css    Tailwind и базовые стили
```

### Где какие данные

| Данные | Где хранятся | Почему |
|---|---|---|
| Метрики мониторинга | читаются на сервере в `page.tsx` через use-case и передаются экрану в props | статичны, страницы собираются при сборке, JavaScript для них в браузер не нужен |
| Сообщения обратной связи | API `/api/messages` + кеш TanStack Query | данные сервера: загрузка, ошибки, кеш; сохраняются после обновления страницы |
| Введённый в форму текст | локальный `useState` во flow | временное состояние интерфейса |

### Сервер и браузер

Все `page.tsx` и `layout.tsx` — серверные компоненты. Директива `"use client"` стоит только
на интерактивных границах: `NavLink` (подсветка активного пункта меню), `QueryProvider`
и `ContactScreen` (форма и список сообщений). Статичный блок «Информация» на странице
контактов рендерится на сервере и передаётся в клиентский экран через prop `info`.

### Проверка данных

Схема формы (`layers/domain/messages/message.ts`) одна для браузера и сервера:
браузер проверяет ввод до отправки, а сервер повторно проверяет полученные данные, потому что
клиенту доверять нельзя. Ответы API проверяются схемой в `infrastructure/http/http-client.ts`,
поэтому в приложение попадают только данные ожидаемого формата.

> Сообщения хранятся в памяти сервера (`message-repository.ts`): они переживают обновление
> страницы, но сбрасываются при перезапуске сервера. В реальном проекте здесь была бы база данных.
